# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

`cgarena` is a Go CLI (single `main` package, module `cgarena`, no external dependencies) that runs many games between bots using a CodinGame-style referee (a Java CLI jar), in parallel, and tallies wins/losses/ties.

## Commands

- Build: `go build -o cgarena .`
- Run with config: `go run . -config config.json -md out.md -html out.html`
- Run with flags: `go run . -r "java -jar test-bin/cellularena-cli-1.0.jar" -p1 "python3 test-bots/cellularena_p1.py" -p2 "python3 test-bots/cellularena_p2.py" -n 10 -t 2 -i 1234 -l results`
- All tests: `go test ./...` and `go test -race ./...`; single test: `go test -run TestReferee_Run .`
- `outcome_test.go`, `concurrency_test.go`, `logdir_test.go`, `noresult_test.go`, `seed_test.go`, `timeout_test.go`, `timeout_unix_test.go` (unix-only: checks that the referee and its child are gone after a timeout), `jsonl_test.go` (results file, stderr files, JSON log check, fault pattern and warning; helper `jsonReferee` sets `$g`/`$l`/`$p1`; also uses the real TryAngle Catch logs in `testdata/`), `interrupt_test.go` (context cancellation, and the second-signal path via the `notifySignals`/`stopSignals`/`exitNow` hooks) and `interrupt_unix_test.go` (unix-only: real SIGINT during `run()`), `stats_test.go` (Wilson values, summary text, `-md`/`-html`/`-summary-json` contents, `-z` validation) use fake `sh` referees in `t.TempDir()` (helper `fakeReferee`) for outcomes, invalid reasons and exit codes (via `run(args)`; `runCapture` in `noresult_test.go` also captures stdout by swapping `os.Stdout`, so those tests must not use `t.Parallel`). Other tests are integration tests: they need `java` and `python3` and use the jar/bots in `test-bin/` and `test-bots/` via paths relative to the repo root (constants in `referee_test.go`).

## Architecture

- `main.go` — `main` just calls `run(args) int`, which parses flags with its own `FlagSet`, merges config, validates and returns the exit code (`exitOK` 0, `exitUsage` 1 (also when writing the results file failed), `exitInvalid` 3 when any game was invalid, or when `Arena.NoResultMessage()` is non-empty: no game was decided and at least one was a double forfeit, in which case `run()` prints that message after the summary; before it, the `Arena.FaultWarnings()` lines). `run()` plays the games through `runArena`, which installs a SIGINT/SIGTERM handler (via the replaceable `notifySignals`/`stopSignals` hooks) and calls `Arena.RunContext` with a context the first signal cancels; a second signal before the run returns calls `exitNow(130)` (`os.Exit`). After the run, `run()` builds one `RunSummary` (`arena.Summary(time.Now())`) and writes `-summary-json` from it (also for interrupted runs); when `arena.Interrupted`, it then prints `InterruptedLine()` and the summary text, skips `-md`/`-html` and the no-result check, and returns `exitSignal` (130). Config is built from CLI flags first, then **values from `-config` JSON override flags** (only non-zero values). Also defines `Player` (name, cmd, W/L/T counters, `Ties` being draws; `WinPct` counts a tie as half a win). Writes Markdown (`-md`, `|` escaped), HTML (`-html`, `html.EscapeString`) and JSON (`-summary-json`, `writeSummaryJSON`) summaries, all from a `RunSummary`; failing to write one exits 1.
- `stats.go` — `wilson(successes, n, z)` (Wilson score interval, `ok` false for n = 0, clamped to [0, 1]), `confidenceLabel(z)` (`"95"` for 1.96), and `RunSummary`/`PlayerSummary`: the JSON summary, whose fields are the run-log entry of spec section 7 (`commit`/`dirty` always null until the run log step fills them; `win_rate`/`ci` null when n = 0; `faults` null without a fault pattern; `results_file` null without a results file; `Z`, `Maps`, `Finished` are `json:"-"` for the text forms). `RunSummary.Text()` is the stdout summary (`Summary: seeds a..b (…)` header, `Name: W W / L L / D D   win rate x%  95% CI [lo%, hi%]` with `   faults n` only with a fault pattern, then `Double forfeits: …   Invalid: … (reasons)`); `Arena.PrintResults()` returns it.
- `arena.go` — `Arena` (also the JSON config schema: `referee`, `players`, `games`, `threads`, `seed`, `log_output`, `swap`, `overwrite`, `out`, `json_check` (`*bool`, nil = on, so a config `false` overrides the flag), `fault_pattern`, `z` (`*float64`, nil = 1.96; `Validate()` requires > 0 and finite, so a config `0` is an error), `summary_json`, `timeout` (type `Duration`, a `time.Duration` that is a Go duration string such as `"45s"` in JSON; the zero `Arena` has no timeout, the `-timeout` flag defaults to 30s); the run totals `Decided` (valid games with a win/loss/draw), `DoubleForfeits`, `Invalid`, `InvalidReasons` are `json:"-"`). `Validate()` requires `Games` and `Threads` ≥ 1, `Timeout` ≥ 0, a compilable `FaultPattern` that is only set with logging on, with `Swap` `Games` a multiple of `len(seatOrders())`, and unique player names (called by `Run()` and by `run()` after the config merge). `Run()` builds the seat orders with `seatOrders()` as `[][]Seat` (`Seat` = `{Index, Name, Cmd}`, `Index` being the position in `Players`; no swap: one order; 2 players: alternate; >2: all permutations via Heap's algorithm on a copy), and with `k = len(order)`: if `Seed` ≤ 0 it sets `Seed` to `randomBaseSeed(Games/k)` (in `[1, 2^31-1]`, keeping the last seed ≤ `maxSeed`), then prints the seed range line (`seedRangeLine`) to stdout after `prepareLogDir`. It then starts `Threads` worker goroutines; workers consume match IDs from a channel, run a `Referee` on their own copy of `order[matchID % k]` with `Seed: gameSeed(Seed, matchID, k)` (= `Seed + matchID/k`, so the k seatings of a map share a seed), and send a `gameResult` over a channel. A single collector goroutine (`collect`) owns all counters: it either counts an invalid game (logging game, seed and reason) or adds each seat's W/L/T to `Players[seat.Index]`. Workers never read `Players`; there is no mutex. `Run()` is `RunContext(context.Background())`. In `RunContext(ctx)`, once `ctx` is cancelled the dispatch loop stops, workers skip remaining jobs, and running referees are killed; the collector ignores results with `Interrupted` set (counting `Killed` ones in `Arena.Killed`), and `Arena.Interrupted` is set if fewer than `Games` finished (`Finished()` = `Decided + DoubleForfeits + Invalid`). The collector also appends each finished (not interrupted) game's `GameRecord` to the results file (`resultsPath()`: `Out`, else `<LogOutput>/games.jsonl` with logging on, else none), opened by `RunContext` after `checkResultsFile` (explicit `Out` only: an existing non-empty file needs `Overwrite`) and `prepareLogDir`; the first write error stops writing and is returned by `RunContext`. It counts `Player.Played` (valid games, double forfeits included) and `Player.Faults`; `FaultWarnings()` lists players with `Played > 0 && Faults == Played`. Names are display-only. Logging is off by default (`-l` defaults to `off`); when enabled (`LogOutput` not empty/"none"/"off"), `Run()` first calls `prepareLogDir`, which never removes the directory: it creates a missing dir, uses an existing one, and returns an error (exit 1 via `run()`) if it holds result files (`isResultFile`: `match_*.json`, `match_*.err`, `games.jsonl`) unless `Overwrite` (`-overwrite` / config `overwrite`) is set, in which case it deletes only those files (not directories, not subdirectory contents).
- `referee.go` — `Referee.Run(matchId)` takes `Seats []Seat` (seat order; build from players with `seatsOf`) and execs the referee command (split naively on spaces, so no quoted args), appending `-pN <cmd>`, `-seed <Seed>` (the exact per-game seed computed by the arena; only if Seed > 0, which `Arena.Run` always ensures) and `-l <log>`. It always returns a non-nil `RefereeResult` (with `Seats` plus per-seat `Players` W/L/T for that game); an invalid game also returns an `*InvalidGameError` and sets `InvalidReason` (`start_failed`, `exit_status_<n>`, `timeout`, `score_count`, `seed_mismatch`, `json_log`). With `Timeout` > 0 it runs the referee via `exec.CommandContext` in its own process group (`setProcessGroup`), and `cmd.Cancel` calls `killProcessGroup` (SIGKILL to `-pid`, so bots the referee started die too); any error after the context expired is `timeout`. `Run(matchId)` is `RunContext(context.Background(), matchId)`; the timeout context is derived from the parent, and an error while the parent is cancelled is checked first and returns `ErrInterrupted` with `Interrupted` set (and `Killed` if the process had started), so an interrupt is never classified as `timeout` or `exit_status_-1`. `proc_unix.go` (`//go:build unix`) and `proc_other.go` (`!unix`, kills only the referee) hold the platform code; check `GOOS=windows go vet ./...` when touching them. `cmd.WaitDelay` (`waitDelay`, 1s) stops `Wait` hanging on pipes held open by grandchildren; an `exec.ErrWaitDelay` after a clean referee exit is treated as success. With logging on it also writes the referee's stderr to `<LogOutput>/match_<g>.err` and, after the stdout checks pass, reads the JSON log (`readGameLog`/`gameLog`: `scores`, `tooltips[].text`, string `summaries`): `EndReason` = last tooltip text; with `JSONCheck`, a read/parse error or `checkScores` mismatch is invalid `json_log`; with a `FaultPattern`, `Faults[j]` is set when some tooltip/summary **line** matches and `namesSeat(line, j)` (`$j` not followed by a digit). Without `JSONCheck` an unreadable log is ignored. `Duration` and `LogFile` are set too. It parses the referee's **stdout**: integer-only lines (trimmed) are per-player scores in seat order, a `seed=` line is the seed. `ProcessResults` sets per-seat `Outcomes` (`win`/`loss`/`draw`/`double_forfeit`/`invalid`): all scores negative → double forfeit, unique max → win, tied max → draw, rest → loss.
- `htmlout.html`, `results/`, `test-results/` — sample/generated outputs, not source. `testdata/` holds two real TryAngle Catch JSON logs used as test fixtures.

## Gotchas

- `main.go` has a leftover unused `buildRefereeCmd`/`shellJoin` path (uses `-d seed=` and `sh -c`) that is not what `Referee.Run` actually does.
- `-o` (old mode) is a stub that only prints a message. `-s` still prints a stale "not implemented yet" message although swapping works (removed in the cleanup step).
- With swap on, seeds are paired (`Seed + g/k`), so tests and scripts that assumed `Seed + g` for swap runs are wrong; without swap it is still `Seed + g`. `seed_test.go`'s `recordingReferee` writes each game's `-seed` and seat commands into its `-l` file to check this.
- Referee scoring parsing assumes the referee prints scores as bare integers on their own lines; any other count of integer lines makes the game invalid (`score_count`).
- `results/` already holds `match_*.json`, so the "Run with flags" / config examples above (`-l results`, `log_output: results`) now exit 1 unless `-overwrite` is added (which deletes those sample files) or another `-l` dir is used.
- Config `"timeout": "0s"` can't disable the timeout, because only non-zero config values override flags (until the precedence flip in the cleanup step); `-timeout 0` does.
- `TestRun_SIGINTKillsRunningReferees` sends a real SIGINT to the test process; that is only safe while `run()` has its handler installed (it waits for the fake referees' PID files first). Don't add tests that signal the process outside a running `run()`.
- With logging on, `-json-check` is on by default, so fake referees in tests that run with `-l` must either write a JSON log whose `scores` match stdout (e.g. `logWriter`) or pass `-json-check=false` / `JSONCheck: noJSONCheck()` (as `recordingReferee` users do); otherwise every game is invalid `json_log`. Logging-on runs also create `match_<g>.err` and `games.jsonl` in the log dir.
- Fake referees writing JSON with `\n` inside strings must use `printf '%s\n' '...'`, not `echo`: `sh`'s `echo` turns `\n` into a real newline and breaks the JSON.
